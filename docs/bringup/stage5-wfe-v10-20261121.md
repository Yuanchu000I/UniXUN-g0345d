# Stage 5 WFE/clock: v9 observation and v10 host result

2026-11-21. Sanitized derived summary of private frozen observations and host
receipts. No original photographs, raw ADT, binaries, device identities or
private raw reports are reproduced.

## Observed boundary

The official seven-stage process remains in Stage 5, after early
PE_init_platform(FALSE,args) returns and within WFE/clock initialization.
UEFI/menu/payload/DarwinBoot handoff have earlier evidence. Complete platform
expert, Stage 6 storage/root and Stage 7 userland are unverified.

The latest v9 photograph shows a white entry band (rows 512–527) and red
classifier slot (rows 480–495). The audited classifier reads the real timebase,
quotient and index before the original shift. This supports timebase=0,
quotient=0, index=0xffffffff and arrival at red pixel stores. It does not prove
final DSB, subsequent shift/UBSAN, a trap PC, exact zero-clock cause, function
return or stability. The photograph lacks an independent full-image transfer
digest; loader/menu text is residual framebuffer content.

## v10 ADT-only candidate

The preceding ADT had arm-io/ranges=(0,0,0xa000000). In the actual diagnostic
XNU source, zero SoC base returns before default-clock initialization and the
running CPU timebase-frequency read. This is a static causal candidate
consistent with the observed values, not a measured trap PC. A prior local
tool's removal of the official nonzero-base check was incorrect.

The official generic generator uses 16 MiB alignment. v10 instead applies an
isolated MSM8996 **64 KiB window adaptation**, because the lowest exported MMIO
is rpm-msg-ram at 0x68000. It sets ranges=(0,0x60000,0x9fa0000) and subtracts
0x60000 from all seven exported reg addresses. Resolved physical addresses,
lengths and top 0xa000000 remain unchanged. Exactly nine u64 fields change,
with ten actual changed bytes. This is a board adaptation, not unchanged
output of the official default generator.

v10 reuses v9's exact 46-patch XNU 8796.121.2 kernel: no rebuild or 47th patch.
Real 19.2MHz, low-address devices, WFE, UBSAN and initialization/refusal guards
remain. Only existing ADT cluster data was patched; FAT metadata, cluster
chains, slack, other files, FD, OEM DTB and fixed envelope stay unchanged.
Legacy boot ID was recomputed.

## Host checks and remaining test

Independent FAT/ADT decoding confirmed the nine-field boundary, seven physical
ranges and real frequency. Independent Windows checks verified hashes,
Android v0 geometry, boot ID, fixed FD/OEM DTB/envelope and GZipStream FD
decompression. Windows checks did not independently decode ADT; the separate
Python audit did. Finalization is ready-for-temporary-device-test with 14 items;
validation binds 12 build-evidence items and 18 inputs. **v10 is untested on hardware**.

The isolated diagnostic record checker retained exit 1 with only
device.soc must match board.toml. The curated publication checker does not
retroactively alter that receipt. Native-only/skip-prelink and absence of
20F66 donor kexts remain material limits.

If 19.2MHz initializes with events/sec unchanged at 1,000,000, the static
expected quotient is 19 and index is 4. The slot could become white before
orange or dark-purple stores overwrite it. These are untested predictions;
colors support only corresponding stores, and absence does not locate a fault.
Future authorized testing uses temporary fastboot boot only. No device command,
reboot or partition write occurred as part of source publication.

The [exact export](../../diagnostics/ios16-20F66/README.md) records the 46 patches
and source pins. Root XNU 8796.101.5 did not produce this kernel.
